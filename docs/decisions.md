## 2026-08-26: G2 ビジュアルの輝度表現に SDK 0.0.14 の textColor 多層方式を採用

### 背景

G2 の ASCII ビジュアルは字形（文字セット帯）だけで濃淡を表現しており、PC 版が持つ「字形＝密度、輝度＝明滅」の二軸が失われていた。SDK 0.0.14 で `textColor`（テキスト輝度 0〜4、コンテナ単位）が追加され、輝度軸を取り戻せる可能性が出た。

### 採用案: 案A→案Bの2段構え

- **案B（本命・クオリティ重視）**: 全画面テキストコンテナを4層重ね（textColor 1〜4、1層に `isEventCapture: 1`）、セルを輝度別の層に振り分ける。4段階×字形6帯＝実質24階調。セルごとの独立明滅は「層の移動」で表現
- **案A（フォールバック）**: 現行1コンテナのまま `TextContainerUpgrade` に textColor を配管（blackout=textColor:0、呼吸=4⇔3 の全画面一律明滅）
- 案Aは案Bの部分集合なので、先に案Aを実装しても捨て作業にならない。案Bの成立条件（テキスト層同士の透過）が NG なら案A止まりに方針転換

### 却下・不採用とした案

- **SDK 0.0.14 の textColor 以外の新機能（長押しイベント・メニュー・音声方向）**: 操作系は Playtron 側の担当領域のため使わない。採用対象は textColor のみ
- **Simulator 0.9.2/0.9.3 の隔離明け（08-29）まで更新を待つ案**: 0.9.2/0.9.3 の変更は画像処理のみで、本プロジェクトはテキスト表示のみ。textColor レンダリング＋長押しは 0.9.0/0.9.1 に入っており、隔離明け 08-27 に 0.9.1 で更新できる

### 制約・前提

- textColor は**コンテナ単位**。セル単位の輝度は SDK に存在しないため、多層への振り分けで疑似実現する
- 999 バイト制限は呼び出し単位のため、層ごとに独立予算（~4×990B）が使える
- 案B着手前の必須検証: ①テキスト層同士の透過（無字部分が下層を隠さないか）②textColor:0 が完全消灯か ③0〜4 と16階調ハードの対応（スクショ実測でガンマ調整）
- 実機は Even App 2.2.9 以上が必要（SDK 0.0.14 の最低要件）。4回送信/フレーム(180ms)が BLE で捌けるかは実機検証
